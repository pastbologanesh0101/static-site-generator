# Static Site Generator

[![Tests](https://github.com/pastbologanesh0101/static-site-generator/actions/workflows/tests.yml/badge.svg)](https://github.com/pastbologanesh0101/static-site-generator/actions/workflows/tests.yml)

A small, Jekyll/Hugo-style **build-time** static site generator written in
pure Python. It reads Markdown content files with YAML front matter,
renders them through Jinja2 templates, and writes a fully static HTML
site (plus an RSS feed) to an output directory. There is no server, no
database, and nothing runs at request time — everything is generated
once, ahead of time, by running a script.

This is distinct from a dynamic web app: the output of `build.py` is
plain files you can host anywhere static assets are served (GitHub
Pages, S3, nginx, a CDN, `python -m http.server`, ...).

## Features

- Markdown content with YAML front matter (`title`, `date`, `tags`,
  `layout`, `draft`)
- Jinja2 templates: a base layout, post layout, page layout, index
  listing, and per-tag listing
- Clean URLs: `content/posts/hello-world.md` -> `output/posts/hello-world/index.html`
- Auto-generated homepage index of published posts, sorted by date
  descending
- Auto-generated per-tag listing pages
- Auto-generated RSS 2.0 feed (`output/feed.xml`)
- Draft posts (`draft: true`) are excluded from the index, tag pages,
  and RSS feed, but still build individually for local preview
- Deterministic, idempotent builds: running the build twice against
  unchanged inputs produces byte-identical output
- Clear, actionable errors on malformed or missing front matter instead
  of a raw stack trace

## Project layout

```
static-site-generator/
├── build.py                # the generator (parsing, rendering, CLI)
├── content/
│   ├── posts/*.md          # blog posts
│   └── pages/*.md          # standalone pages (e.g. About)
├── templates/
│   ├── base.html           # shared HTML shell
│   ├── post.html           # extends base.html
│   ├── page.html           # extends base.html
│   ├── index.html          # homepage post listing
│   └── tag.html            # per-tag post listing
├── static/
│   └── css/style.css       # copied into output/ unchanged
├── output/                 # generated by build.py (git-ignored)
├── tests/
│   └── test_build.py       # unit tests
└── .github/workflows/tests.yml
```

## Requirements

- Python 3.11+
- `markdown`, `Jinja2`, `PyYAML` (see `requirements.txt`)

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Building the site

```bash
python build.py --content content/ --templates templates/ --output output/
```

Optional flags:

- `--static PATH` — static assets directory to copy into `output/`
  unchanged (default: a `static/` directory next to `--content`)
- `--site-url URL` — base URL used to build absolute links in the RSS
  feed (default: `https://example.com`)

The build is destructive-but-deterministic: `output/` is deleted and
regenerated fresh on every run, so stale files never linger and the
result is a pure function of `content/`, `templates/`, and `static/`.

## Previewing locally

```bash
python build.py --content content/ --templates templates/ --output output/
cd output
python -m http.server 8000
# then open http://localhost:8000/
```

## Front matter schema

Every content file must start with a `---`-delimited YAML block:

```markdown
---
title: My Post Title       # required
date: 2026-01-05            # required for posts (YYYY-MM-DD)
tags: [python, tutorial]    # optional, list or comma-separated string
layout: post.html           # optional (default: post.html for posts, page.html for pages)
draft: true                 # optional bool, default false
---

Markdown body goes here.
```

| Field    | Required             | Applies to  | Notes                                                        |
| -------- | --------------------- | ----------- | ------------------------------------------------------------- |
| `title`  | yes                    | posts+pages | Rendered as the page's `<h1>` / `<title>`                     |
| `date`   | yes (posts), no (pages) | posts       | `YYYY-MM-DD`; drives sort order, index, tags, RSS              |
| `tags`   | no                     | posts       | List (`[a, b]`) or comma-separated string                     |
| `layout` | no                     | posts+pages | Template filename in `templates/`                             |
| `draft`  | no (default `false`)  | posts       | Excludes the post from index/tags/RSS; still builds standalone |

Missing or malformed front matter (no `---` block, unterminated block,
missing `title`/`date`, or an unparsable `date`) raises a
`FrontMatterError` naming the offending file and field(s), instead of
crashing the whole build with an unrelated traceback.

## Template variables available

Rendered into `post.html` / `page.html`:

| Variable   | Type                | Description                                  |
| ---------- | ------------------- | --------------------------------------------- |
| `title`    | `str`                | From front matter                             |
| `date`     | `datetime` or `None` | From front matter (posts only)                |
| `tags`     | `list[str]`          | From front matter                             |
| `draft`    | `bool`                | Whether this item is a draft                  |
| `content`  | `Markup` (safe HTML) | The Markdown body, already converted to HTML  |
| `metadata` | `dict`                | The raw front matter dict, for custom fields  |
| `url`      | `str`                 | This item's own clean URL, e.g. `/posts/x/`   |
| `posts`    | `list[ContentItem]`   | All published posts (for cross-linking)       |

Rendered into `index.html` and `tag.html`:

| Variable | Type                | Description                                    |
| -------- | ------------------- | ------------------------------------------------ |
| `posts`  | `list[ContentItem]`  | Published posts, sorted by date descending        |
| `tag`    | `str`                 | (tag.html only) the tag name being listed         |

Each item in `posts` exposes `.title`, `.date`, `.tags`, `.url`,
`.draft` — used in templates as `post.title`, `post.date`, etc.

## Clean-URL convention

- `content/posts/<slug>.md` -> `output/posts/<slug>/index.html`, served at `/posts/<slug>/`
- `content/pages/<slug>.md` -> `output/<slug>/index.html`, served at `/<slug>/`
- Tag pages: `output/tags/<tag-slug>/index.html`, served at `/tags/<tag-slug>/`
- Homepage: `output/index.html`, served at `/`
- RSS feed: `output/feed.xml`, served at `/feed.xml`

The slug is the filename stem (`hello-world.md` -> `hello-world`)
unless overridden with a `slug:` front matter field.

## Running the tests

```bash
pip install -r requirements.txt pytest
python -m pytest tests/ -v
```

The test suite covers Markdown rendering, front-matter propagation into
templates, the clean-URL convention, index sorting/draft exclusion,
per-tag listing correctness, byte-for-byte static asset copying, RSS
feed correctness, build determinism (hash comparison across two
builds), and clear failure on malformed/missing front matter.
